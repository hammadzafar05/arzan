# AGENTS.md

Guidance for AI coding agents working in an Arzan app. Read this before changing code.

## What this is
One Cloudflare Worker serves a React single-page app (static assets) and a Hono API under `/api/*`. Data lives in D1 (SQLite) through Drizzle. Auth is Better Auth. Everything must keep working on the **Workers Free plan**.

## Commands
- `npm run dev`: app + API + local D1 on http://localhost:5173 (the first run creates `.dev.vars` with a random secret)
- `npm test`: Vitest API tests (real in-memory D1 via `getPlatformProxy`)
- `npm run test:e2e`: Playwright (needs a built app; it runs `npm run preview` itself)
- `npm run check`: lint + typecheck + test + build. **Run it before every commit.**
- `npm run db:generate`: create a migration after editing `worker/db/schema.ts`

## Rules
1. **Free tier first.**
   - Keep pages static (no SSR); only `/api/*` may run the Worker.
   - Avoid CPU-heavy work per request (10 ms budget). Never replace `worker/auth/password.ts` with pure-JS hashing.
   - Add indexes for columns you filter or sort on; paginate lists.
2. **Migrations:**
   - Edit `worker/db/schema.ts`, then run `npm run db:generate`. Never hand-edit a migration that has shipped.
   - `npm run db:generate` also regenerates `worker/db/migrations.gen.ts`, which the Worker bundles. Commit both; a test fails if they drift.
   - Migrations apply automatically on the first request (`worker/db/migrate.ts`); don't add a `wrangler d1 migrations apply` step.
   - Production changes are additive only (new tables, and new columns with defaults).
3. **Multi-row writes use `db.batch([...])`** (D1's transaction). Validate first, then write in one batch.
4. **Auth:**
   - Protect API routes by mounting them after `requireUser` in `worker/app.ts`, and read the user with `c.get("user")`.
   - Never trust user ids from the request body.
   - The client reads the session from `sessionQuery` (TanStack Query). After anything that changes who is signed in, call `refreshSession(queryClient)`. Never `queryClient.clear()`: it detaches observers.
5. **Security:**
   - `csrf()` in `worker/app.ts` blocks cross-site form posts. Keep it ahead of every route.
   - Never add CORS headers with credentials, so browsers keep blocking cross-site JSON requests.
   - Send post-login redirects through `safeRedirect()`. It blocks open redirects such as `//evil.com` and `/\evil.com`.
   - `public/_headers` sets a strict CSP (no inline scripts or styles from other origins). New third-party origins must be added there, or the browser blocks them. The e2e tests fail on any CSP violation. Only Cloudflare Web Analytics (`cloudflareinsights.com`) is allowed by default.
   - Emails are credentials. Never log their links outside local dev (`sendEmail` already enforces this).
6. **Errors:** API errors are `{ error: "Human sentence" }` with a proper status. Show them to users as they are. Write them as instructions ("Please sign in to continue.").
7. **UI:**
   - Use the shadcn/ui components in `src/components/ui` and the `Field` / `InputError` / `SectionHeading` helpers.
   - Signed-in pages go in `src/routes/_app/` and start with `<PageHeader>`. Signed-out pages go in `src/routes/_guest/` inside `<AuthLayout>`.
   - Call `useTitle()` on every page.
   - Check phone width (390 px) and dark mode for every UI change.
8. **Tests:**
   - Every API behaviour gets a test: the happy path plus the refusal.
   - Use `createTestApp()`. Each `client()` is one browser with its own cookies and IP.
   - Emails land in `devOutbox`; use `lastEmailTo()` to follow links.
9. **Style:** Biome formats and lints (`npm run format`). Strict TypeScript, no `any` outside tests.

## Where things are
- `worker/app.ts`: middleware order and route mounting
- `worker/auth/index.ts`: Better Auth options (plugins go here)
- `worker/email/`: `sendEmail()` and templates
- `shared/config.ts`: app name and auth rules, shared by the Worker and the app
- `src/config.ts`: layout choice and navigation
- `src/routeTree.gen.ts`: generated by the router plugin; don't edit it
